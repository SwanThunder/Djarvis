# Djarvis

[English version](README.md)

Djarvis — персональный интеллектуальный помощник для ведения дел и привычек, общения и поиска информации в интернете.

Репозиторий сейчас содержит организационный каркас и документы. Приняты Flutter для интерфейса, Python для ядра и фоновой логики и управляемый приложением частный PostgreSQL; решения T1–T6, фазы Ф0–Ф7 и критерии их приёмки тоже утверждены. Архитектура процессов и структура каталогов core/ + ui/ утверждены (ADR-022); схема базы, API и модули ещё рассматриваются. Работающего приложения пока нет; Ф0 требует отдельного явного разрешения.

## Структура

Ниже — существующий организационный каркас; в этих каталогах пока нет кода приложения. Утверждённая для будущего кода структура core/ + ui/ описана в [плане реализации](docs/architecture/IMPLEMENTATION_PLAN.ru.md); создать её можно после отдельного разрешения Ф0.

```text
src/
  core/           Основная логика и сценарии работы
  agents/         Реализации агентов и их координация
  tools/          Инструменты, вызываемые ассистентом
  integrations/   Подключения внешних сервисов и моделей
  memory/         Логика памяти и доступа к знаниям
  interfaces/     Интерфейсы приложения; конкретные каналы ещё не выбраны
config/           Конфигурация без секретов
data/
  db/             Локальная папка каркаса; будущий PostgreSQL размещается в %LOCALAPPDATA%
  files/          Локальная папка каркаса; рабочие файлы приложения будут вне репозитория
cache/            Восстанавливаемый кэш
logs/             Журналы работы приложения
tmp/              Временные файлы
Plan/             Общий журнал разработки на английском и русском
docs/             Правила разработки и согласованные решения
scripts/          Служебные скрипты
tests/            Тесты
assets/           Статические ресурсы
```

Папки data/, cache/, logs/ и tmp/ могут содержать локальные материалы подготовки; их рабочее содержимое исключено из выгрузки по правилам проекта. Не очищай их как часть изменения структуры. У установленного приложения частная рабочая база и файлы пользователя располагаются вне репозитория, в профиле Windows. В папке data/db сейчас нет рабочей базы Djarvis.

## Разработка

- Перед каждой задачей прочитай [правила проекта](docs/PROJECT_RULES.ru.md).
- Перед редактированием проверь и обнови [общий журнал](Plan/WORK_LOG.ru.md).
- Согласованные решения по архитектуре сохраняй в [реестре решений](docs/architecture/DECISIONS.ru.md).
- Изучи [продукт](docs/PRODUCT.ru.md), [принятые решения](docs/architecture/DECISIONS.ru.md), [архитектуру и фазы](docs/architecture/IMPLEMENTATION_PLAN.ru.md) и [краткий обзор архитектуры](docs/architecture/ARCHITECTURE_REVIEW.ru.md). Фазы приняты; архитектура/каталоги утверждены, схема, API и модули требуют отдельного согласования.
- Следуй [обязательному дизайну Djarvis](docs/DESIGN.ru.md), заданному владельцем; выбор технологий должен сохранять этот дизайн.
- Перед планированием реализации изучи [подробный проект ядра планера, данных и взаимодействия](docs/architecture/PLANNER_CORE.ru.md).
- Используй [план оставшегося проектирования и решений](docs/architecture/REMAINING_PLAN.ru.md): восемь направлений, вопросы с выбором, критерии готовности и восстановление контекста.
- Изучи [подробный план оставшихся компонентов](docs/architecture/COMPONENT_PLAN.ru.md): CP01–CP20, зависимости, результаты проектирования и этапы согласования.
- Рассмотри конкретные предложения: [основа CP01–CP07](docs/architecture/FOUNDATION_DESIGN.ru.md), [помощник CP08–CP14](docs/architecture/ASSISTANT_DESIGN.ru.md), [выпуск CP15–CP20](docs/architecture/DELIVERY_DESIGN.ru.md). Принятые ответы и несогласованные технические рекомендации отмечены отдельно; документы не являются реализацией.
- Смотри [сводку статуса проекта](docs/STATUS.ru.md) — принятые решения, открытые вопросы и оставшаяся работа — и [разбор компоновки главного экрана](docs/architecture/DASHBOARD_LAYOUT_REVIEW.ru.md) — бриф компоновки и плавающая кнопка микрофона.
- Поддерживай английскую и русскую документацию в отдельных синхронизированных файлах.
- Перед программированием представь и обсуди план реализации; начинай только после согласования владельцем.

Репозиторий: [SwanThunder/Djarvis](https://github.com/SwanThunder/Djarvis).
