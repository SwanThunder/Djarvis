# Djarvis

[English version](README.md)

Djarvis — персональный интеллектуальный помощник для ведения дел и привычек, общения и поиска информации в интернете.

Сейчас репозиторий содержит структуру проекта и документы разработки/дизайна. Flutter UI и необходимый UI-код на Dart выбраны в ADR-001; PostgreSQL как локальная база бэкенда — в ADR-002; Python для логики ядра планировщика/фонового процесса со своей упакованной средой выполнения — в ADR-003; управление приложением жизненным циклом изолированной локальной копии PostgreSQL — в ADR-004. В текущей версии нет удалённого бэкенда или облачного хранилища Djarvis; разрешённые внешние подключения рассматриваются отдельно, будущая облачная синхронизация ещё требует проектирования. Точные версии, драйверы, схема, распространение/упаковка среды выполнения и базы и остальная архитектура не утверждены. Эти решения не разрешают реализацию приложения; работающего приложения пока нет.

## Структура

```text
src/
  core/           Основная логика и сценарии работы
  agents/         Реализации агентов и их координация
  tools/          Инструменты, вызываемые ассистентом
  integrations/   Подключения внешних сервисов и моделей
  memory/         Логика памяти и доступа к знаниям
  interfaces/     Интерфейсы приложения; конкретные каналы ещё не выбраны
config/           Конфигурация без секретов
data/
  db/             Постоянные локальные данные приложения (детали размещения PostgreSQL не выбраны)
  files/          Постоянные пользовательские файлы
cache/            Восстанавливаемый кэш
logs/             Журналы работы приложения
tmp/              Временные файлы
Plan/             Общий журнал разработки на английском и русском
docs/             Правила разработки и согласованные решения
scripts/          Служебные скрипты
tests/            Тесты
assets/           Статические ресурсы
```

`data/` предназначена для постоянного хранения, её нельзя очищать как кэш. В `cache/` хранятся только восстанавливаемые данные. Рабочие данные, секреты, логи и временные файлы исключены из Git. В папке базы пока нет самой базы и схемы.

## Разработка

- Перед каждой задачей прочитай [правила проекта](docs/PROJECT_RULES.ru.md).
- Перед редактированием проверь и обнови [общий журнал](Plan/WORK_LOG.ru.md).
- Согласованные решения по архитектуре сохраняй в [реестре решений](docs/architecture/DECISIONS.ru.md).
- Изучи [описание продукта](docs/PRODUCT.ru.md), [первое предложение архитектуры](docs/architecture/PROPOSAL.ru.md) и [реестр решений](docs/architecture/DECISIONS.ru.md); ADR-001 выбирает Flutter/Dart для UI, ADR-002 — локальный PostgreSQL, ADR-003 — Python для ядра/фоновой логики, ADR-004 — управление приложением жизненным циклом изолированного локального экземпляра PostgreSQL. Точная упаковка и остальная архитектура не утверждены.
- Следуй [обязательному дизайну Djarvis](docs/DESIGN.ru.md), заданному владельцем; выбор технологий должен сохранять этот дизайн.
- Перед планированием реализации изучи [подробный проект ядра планера, данных и взаимодействия](docs/architecture/PLANNER_CORE.ru.md).
- Используй [план оставшегося проектирования и решений](docs/architecture/REMAINING_PLAN.ru.md): восемь направлений, вопросы с выбором, критерии готовности и восстановление контекста.
- Поддерживай английскую и русскую документацию в отдельных синхронизированных файлах.
- Перед программированием представь и обсуди план реализации; начинай только после согласования владельцем.

Репозиторий: [SwanThunder/Djarvis](https://github.com/SwanThunder/Djarvis).

Следующий шаг — обсудить подробный проект ядра планера, данных и взаимодействия и решить его открытые вопросы до согласования реализации. Flutter UI, направление Python для ядра/фоновой логики и управление приложением локальным PostgreSQL выбраны в узких границах; версии, драйверы, упаковка и остальные архитектурные решения требуют согласования. Требуются ежедневные локальные копии, копии перед изменениями структуры/миграцией и настраиваемое хранение по умолчанию семь дней. Полный запрошенный объём продукта и обязательный дизайн сохранены в документации. Копия исходных файлов в GitHub не сохраняет локальные пользовательские данные; перед рискованными изменениями для них нужны отдельные резервные копии.
