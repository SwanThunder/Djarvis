# План оставшегося проектирования и согласований

[English version](REMAINING_PLAN.md) · [Утверждённые решения](DECISIONS.ru.md) · [Подробный проект ядра планера](PLANNER_CORE.ru.md)

Дата: 2026-11-03. Статус: проектирование, не разрешение на реализацию. Документ описывает оставшиеся направления работы, не сокращая запрошенный объём продукта. Все рекомендации ниже остаются предложениями, пока владелец явно их не примет. Выбор версий, планы реализации и программирование требуют отдельного согласования.

## 1. Текущая основа и учёт решений

В репозитории есть каркас и двуязычные спецификации продукта, дизайна, архитектуры и планировщика. Работающего приложения, схемы базы данных или установщика нет. Языковая модель для разработки загружена и прошла краткую проверку запуска; это не проверенная производственная голосовая система и не измерение производительности CPU при 8 ГиБ. См. [оценку локальной модели](../LOCAL_MODEL.ru.md).

Утверждённые направления технологий: Flutter для UI (ADR-001), локальный PostgreSQL (ADR-002), Python для логики ядра/фонового процесса со средой выполнения под управлением приложения (ADR-003), управление приложением запуском/остановкой изолированного PostgreSQL без консоли (ADR-004). Автоматические локальные копии создаются ежедневно и перед изменением структуры/миграциями; срок хранения по умолчанию — семь дней, расписание и срок хранения настраиваются. Собственный сервер активации или хранилище пользовательских данных в облаке не утверждены.

Новые подтверждённые правила планировщика: каждый ввод явного крайнего срока только с датой требует запроса времени; дополнительные поля задач имеют общую настройку отображения и могут раскрываться отдельно в каждой задаче; неделя привычек начинается в понедельник, дни паузы исключаются из оценки, серия замораживается на паузе, исправления сохраняют историю. Это не превращает окно размещения плановой даты 06:00–22:00 в крайний срок.

У каждого нерешённого решения ниже есть стабильный ID. Вопросы выдаются небольшими группами вариантов с выбором; интерфейс ответов также допускает свободный текст. Рекомендуемый или заранее выбранный вариант не считается принятым, пока владелец его не отправит. Неизвестные ответы из прежних пронумерованных сообщений нельзя восстанавливать догадками.

## 2. Направление A — ядро, процессы и контракты

Предлагаемая структура: Flutter отображает модели чтения; один Python-хост в пользовательском сеансе владеет командами, политиками, планированием, напоминаниями и очередями интеграций. Хост управляет собственной базой PostgreSQL и изолированными рабочими процессами моделей/речи. Закрытие окна оставляет хост и прослушивание ключевой фразы активными; «Полностью выйти» останавливает захват звука, рабочие процессы и частную базу. Повторный запуск приложения подключается к существующему хосту, а не открывает второй процесс-владелец каталога данных.

Правила предметной области и сценарии приложения не импортируют Flutter, фреймворки вывода моделей или SDK поставщиков. Предлагаемые модули Python: `domain`, `application`, `planning`, `storage`, `conversation`, `permissions`, `integrations` и `platform_windows`. Это логические границы, а не поручение создавать пакеты сейчас. Существующий каталог папок — каркас; сопоставить с ним модули можно после рассмотрения.

Рекомендуемый локальный транспорт: версионируемый HTTP API команд/запросов и поток событий WebSocket, привязанные только к loopback-интерфейсу и аутентифицируемые секретом на время запуска, переданным через защищённый локальный канал. Не помещать секрет в URL или журналы, не открывать слушатель для локальной сети и не выдавать UI учётные данные базы. FastAPI — кандидат, но не утверждённая зависимость. Альтернатива: именованные каналы Windows с ACL пользователя; это исключает слушающий HTTP-порт, но требует больше нативной работы и другого адаптера Android.

Предлагаемый конверт запроса: ID действия, версия контракта, ID/ревизии целей, типизированные данные и контекст разрешений. Состояния ответа различают уточнение, необходимость подтверждения, отказ, конфликт, локальное применение и постановку во внешнюю очередь. Подтверждение поставщика приходит отдельным последующим событием. События содержат ревизии; при переподключении клиент получает актуальную модель чтения, а не предполагает, что получил все временные события. Отмена генерации не означает отмену уже зафиксированного действия.

Неоднозначная цель или предполагаемая дата всегда требуют уточнения, даже если пользователь отключил подтверждения изменений задач. Уточнение определяет намерение; сохранённое разрешение не может угадывать, какую из нескольких встреч имеет в виду пользователь.

Речь пользователя, UI и запланированные предложения проходят через один и тот же шлюз команд. Модель получает узкие инструменты, а не произвольный SQL или выполнение команд оболочки. Результаты поиска, письма и содержимое файлов — недоверенные данные, они не могут выдавать разрешения. Пользователь выдаёт возможность в настройках, может отозвать её; перед выполнением разрешение проверяется повторно.

Решения: **A1** транспорт; **A2** область сохранённого разрешения не подтверждать изменения задач (рекомендация: явные категории действий с задачами, видимые пользователю и отзываемые); **A3** действия с устройством (рекомендация: список разрешённых программ/путей и явное подтверждение для разрушительных или мешающих действий). Отправка писем и удаление/перезапись пользовательских файлов всегда требуют подтверждения; изменение цели/нагрузки привычки всегда требует принятия предложения.

Критерии готовности: рассмотренные контракты и владение процессами; сценарии дублирующейся команды и переподключения; неоднозначные цели при отключённых подтверждениях; отклонение устаревшего подтверждения; отзыв разрешения для операции в очереди; восстановление после сбоя хоста/рабочего процесса; демонстрация прекращения захвата микрофона при отключении и «Полном выходе». Программирование этих проверок ждёт согласования.

## 3. Направление B — локальный PostgreSQL, схема и восстановление

Рекомендуемое размещение: файлы среды выполнения под управлением приложения отдельно от постоянных данных пользователя и удаляемого кэша. Производственные пользовательские данные хранить в явно выбранном каталоге данных пользователя, не в исходном дереве или каталоге установки. PostgreSQL слушает только локально на управляемом свободном порту, использует отдельную роль базы и аутентифицированные соединения, не присваивает себе и не останавливает постороннюю установку. При запуске проверяются идентичность/версия кластера и отсутствие второго хоста, управляющего тем же кластером. Дистрибутив точных бинарных файлов и совместимость с Windows 10 требуют проверки.

Кандидат на драйвер — Psycopg 3 с ограниченным пулом соединений и короткими транзакциями. Выбрать совместимые сочетания Python/PostgreSQL/драйвера и упаковать вместе; пользовательскому сценарию не нужны глобальный Python, ручной pip, Docker или видимая консоль. Встроенный дистрибутив Python — возможный способ упаковки; замороженные исполняемые файлы — альтернатива для сравнения с нативными зависимостями речи/драйвера. Точные версии и способ упаковки не выбраны.

[Проект ядра](PLANNER_CORE.ru.md) описывает логическую схему: задачи/шаблоны, устойчивые вхождения повторов, размещения, проекты, привычки и измерения, события календаря/сопоставления поставщиков, заметки, напоминания/доставки, разрешения с ограниченной областью, действия/аудит/исходящая очередь, срок хранения разговоров и ревизии планирования. Следующее рассмотрение схемы должно определить столбцы, ограничения, внешние ключи, политику удаления, индексы и миграции. Идентичность вхождения задачи должна быть отдельна от перемещаемого размещения и необязательного срока. Именованный часовой пояс хранить отдельно от UTC-моментов.

Рекомендация по конкурентному доступу: каждая запись, влияющая на планирование, включая синхронизацию календаря, использует одну и ту же короткую блокировку планирования для профиля и увеличивает ревизию. Принятие плана захватывает блокировку, повторно проверяет входные данные и записывает изменения атомарно. Блокировка базы не должна удерживаться в ожидании пользователя, вывода модели или сети. Изменение строки, не влияющее на план, не обязано делать предложение дня недействительным.

Процесс резервного копирования: создать согласованный дамп базы и манифест вложений; сохранять неизменяемое содержимое ссылочных вложений, пока копия создаётся; проверить архив и восстановить его в изолированную временную базу до заявления о возможности восстановления. Не копировать работающий каталог данных PostgreSQL как обычную резервную копию приложения. Удалять старые копии только после успешной проверки новой. В обычные переносимые копии планировщика не включать веса моделей, удаляемый кэш и секреты OAuth.

Процесс миграции: проверить свободное место и версии, создать необходимую восстанавливаемую копию, остановить несовместимые процессы, применить версионируемую миграцию, проверить ограничения и перезапустить ядро. При неудачном обновлении сохранить путь восстановления. Откат одних бинарных файлов недостаточен после несовместимого изменения схемы; крупные обновления PostgreSQL требуют отдельной рассмотренной процедуры миграции.

Решения: **B1** место резервных копий (рекомендация: настраиваемая папка вне каталога активных данных); **B2** шифрование/восстановление копий (рекомендация: переносимый экспорт, зашифрованный паролем, и отдельно спроектированное восстановление ключа); **B3** взаимодействие восстановления и удаления данных. Предлагаемый интерфейс восстановления показывает дату/версию/содержимое архива и предупреждает о замене более новых данных. Восстановление архива до удаления не должно молча возвращать удалённые разговоры. Решить, исключать ли разговоры из копий или инвалидировать/пересоздавать затронутые архивы после удаления. Локальная защита учётных данных Windows сама по себе не делает копию переносимой на другой компьютер.

Критерии готовности: рассмотрение SQL-схемы; сценарии перезапуска/сбоя/нехватки места; отсутствие конфликта владения кластером между процессами; успешное восстановление с вложениями; восстановление после неудачной миграции; проверка срока хранения и удаления разговоров. В рамках этой задачи проектирования база не устанавливается и не инициализируется.

## 4. Направление C — экраны и обязательный визуальный дизайн

[Визуальная спецификация владельца](../DESIGN.ru.md) остаётся обязательной: тёмный Glassmorphism/Bento, узкая левая боковая панель, контекстная верхняя панель с поиском и профилем/действиями, футуристическая круговая визуализация помощника над панелью дня, без фонового изображения. Должны работать все три точные палитры и независимые режимы Glass/Solid, включая непрозрачные вложенные поверхности Solid.

Предлагаемая навигация: Сегодня, Задачи, Календарь, Привычки, Проекты, Заметки, Разговор, Настройки. Экран «Сегодня» содержит помощника, текущий/следующий блок, остаток плана дня и прогресс привычек. Нераспределённая работа и предупреждения о сроках явно отличаются от блоков с заданным временем. Предварительный просмотр команды подсвечивает, какие именно записи будут изменены. При конфликте календаря отображаются обе версии и последствия выбора каждой.

Разделы настроек: оформление; планирование и доступное время; привычки; голос/персонаж/микрофон; инициативные сообщения/тихие часы; подключения и возможности; локальные данные/история/копии; модели/загрузки; подписка. Глобальный поиск сначала ищет среди разрешённых локальных записей; интернет-поиск запускается как явное действие помощника. Для пустого экрана, загрузки, офлайн-состояния, отказа в разрешении, конфликта, подготовки модели и истечения лицензии нужны настоящие макеты, а не вымышленные демонстрационные данные.

Решения: **C1** начальная палитра/материал (предложено `deep-blue-pink` + Glass); **C2** плотность и вид дня по умолчанию (рекомендация: комфортная плотность, временная шкала с компактными карточками дел/привычек); **C3** нужен ли отдельный полноэкранный раздел «Разговор» наряду с панелью помощника. Отображение дополнительных полей уже выбрано; скрытые поля сохраняют данные.

Критерии готовности: рассмотренная карта экранов/состояний и нефункциональные макеты до программирования UI; шесть сочетаний темы и материала; клавиатура/фокус/уменьшение движения; читаемое масштабирование; фактические измерения контраста и проверка эффектов вместе с голосовым стеком на базовом устройстве. Не менять молча утверждённое предпочтение Glass только потому, что устройство работает медленно.

## 5. Направление D — семантика планировщика и привычек

Подтверждённые правила записаны в [PRODUCT](../PRODUCT.ru.md) и [PLANNER_CORE](PLANNER_CORE.ru.md): четыре приоритета; раздельные просрочка крайнего срока и пропуск размещения; запрос недостающей длительности до автоматического планирования; блокировка размещения, заданного вручную; согласие на разделение отдельно для каждой задачи; повторение от исходной точки с отдельными незавершёнными вхождениями; четыре типа привычек; расписания по фиксированным дням и гибкая частота по разным успешным дням; пропуски привычек не становятся долгом задач.

Предлагаемое создание задачи: обязательно название, обычный приоритет по умолчанию, другие основные поля необязательны, если их не требует запрошенная операция. Для плановой даты только с датой используется 06:00–22:00; при вводе крайнего срока без времени всегда задаётся вопрос о времени. Если пользователь вручную задаёт время начала без известной длительности, рекомендуется показывать видимый маркер только времени начала, а не проверенный занятый интервал. Перед планированием запросить длительность либо позволить пользователю явно исключить этот маркер из данной попытки; не считать молча неизвестное время окончания свободным. Автоматический планировщик не придумывает длительность и не меняет срок молча.

Предлагаемый алгоритм: получить ревизию планирования; собрать доступность, заблокированные встречи/блоки и правила перерывов; запросить недостающие обязательные данные; построить допустимые размещения; отдавать предпочтение срокам и приоритетам, соблюдая явные блокировки; объяснить нераспределённую работу и нехватку времени; показать изменения; применить их только с требуемым подтверждением/разрешением и повторной проверкой ревизий. Это не заявление о глобально оптимальном плане. UI должен отличать срок, который нельзя соблюсти, от просто перегруженного предпочтительного окна.

При рассмотрении повторов охватить дневные/недельные/месячные схемы, интервальные точки отсчёта, исключения, изменения одного вхождения или его и последующих, отмену без удаления исторического долга. Рекомендация для отсутствующей даты месяца: явно выбирать, пропустить её или использовать последний день месяца. Не смещать молча точку отсчёта повторения. В спецификации времени также определить события на весь день и с заданным временем, нормализацию занятости/свободного времени и явную политику для несуществующего или повторяющегося местного времени при переходе на летнее/зимнее время.

Модель привычек: отдельные дневные измерения, оцениваемый день/период, история версий цели и исправленные записи. Пауза исключает дни паузы из оценки и замораживает серию. Для гибкой недельной частоты правило для недели с частичной паузой остаётся открытым: рекомендация — считать неделю с недостаточным числом доступных дней приостановленной/неполной, а не молча снижать цель или записывать пропуск. Для воздержания нужна явная отметка успеха; молчание не доказывает успех. Предложения изменить цель/нагрузку никогда не применяются автоматически.

Решения: **D1** минимальное создание/обычный приоритет по умолчанию и маркер только времени начала; **D2** поведение при смене часового пояса (рекомендация: сохранять исходный часовой пояс события и явно предлагать адаптировать повторяющиеся личные процедуры); **D3** отсутствующие числа месяца; **D4** квота при частичной недельной паузе и точные определения серий для фиксированного/гибкого расписаний; **D5** исправления привычек задним числом (рекомендация: разрешить, хранить историю исправлений, пересчитывать затронутую статистику); **D6** длительность/буфер перерывов и правила сегментов задачи (рекомендация: настраиваемые пределы, проверять положительную длительность сегментов и их сумму относительно согласованной длительности задачи, требовать явного действия завершения задачи, а не выводить выполнение из истёкших временных блоков). Нужно выбрать, обязательны ли отметки всех сегментов для завершения задачи.

Критерии готовности: разобранные примеры плановой даты без времени и уточнения срока; несколько просроченных вхождений повтора; позднее выполнение без сдвига графика; пропуски/повторы DST; невозможные планы; устаревшие предложения; сумма сегментов и явное завершение; недели с паузой/исправления/воздержание. Алгоритм и схема пока не выполнялись.

## 6. Направление E — локальный разговор, речь и персонажи

Предлагаемая цепочка: захват микрофона → локальный детектор ключевой фразы/VAD → локальное распознавание речи → намерение/контекст → локальная языковая модель → команды под управлением политик или ответ → локальный синтез речи. Обнаружение перебивания должно работать во время озвучивания; отключение микрофона прекращает любой захват, включая обнаружение ключевой фразы. По умолчанию предлагается не хранить исходное аудио. История разговора остаётся настраиваемой пользователем, удаляемой и необязательной; временные буферы сессии и минимальный аудит действий не должны становиться скрытой стенограммой.

Бюджеты ресурсов должны учитывать Python-хост, PostgreSQL, UI и рабочие процессы речи/моделей вместе. Кандидаты небольших LLM и загрузка рабочих процессов по требованию требуют измерений точности/задержки. Одновременное хранение нескольких крупных моделей в памяти — не проверенная стратегия для 8 ГиБ; выгрузка рабочих процессов не должна ломать перебивание или фоновое ожидание ключевой фразы. Оценённая модель 4B для разработки ещё не выбрана как базовая производственная модель.

Кандидаты сред выполнения: llama.cpp для языкового вывода и sherpa-onnx для автономных речевых компонентов. Лицензии моделей проверяются отдельно от лицензий сред выполнения. Поддержка обнаружения ключевых слов не доказывает точное распознавание любой введённой пользователем фразы; произвольные фразы требуют обучения/проверки и явного ответа о неподдерживаемой фразе, а не притворства, что она принята.

Каталог моделей sherpa-onnx содержит варианты ASR для русского и английского языков; лицензия Apache-2.0 среды выполнения не определяет лицензии конкретных весов. Для как минимум одного старого пакета GigaAM на русском указаны некоммерческие условия, поэтому ни один выпуск GigaAM не утверждён для этого коммерческого продукта без проверки конкретного артефакта. Документированные предварительно обученные модели ключевых слов не подтверждают поддержку пользовательской русской фразы. Qwen3-TTS 0.6B Base — кандидат для оценки клонирования речи с русским/английским языками и условиями Apache-2.0 в карточке модели; варианты работы на CPU не являются официальным тестом задержки/памяти на Windows с 8 ГиБ. Ни один кандидат не выбран для выпуска.

Запрошенные личности Джарвиса, Рика Санчеза и Себастьяна и узнаваемые голоса остаются требованиями. Локальный MP3 Рика — ориентир, а не доказательство разрешения или готовая производственная модель голоса. До выбора ресурсов определить точную версию дубляжа/языка и получить необходимые разрешения на коммерческое использование. Лицензия ПО/весов речевой модели не даёт прав на персонажа или запись. Молча выбирать обобщённую замену нельзя. Для технических оценок можно применять надлежащим образом лицензированные нейтральные тестовые аудиоматериалы, не объявляя запрошенные производственные голоса готовыми.

Предлагаемые состояния помощника: микрофон выключен, ожидание ключевой фразы, слушает, обрабатывает, говорит, готовит модели, ограниченный режим/ошибка. Состояние видно в главном окне и области уведомлений. Тайм-аут завершает сеанс; «Хватит» или выбранная английская команда немедленно завершает его. Прерванный голосовой ответ не возобновляется автоматически поверх следующей реплики пользователя.

Решения: **E1** точная версия голоса/языка (Рик: предоставленный образец / другая лицензированная версия; Джарвис и Себастьян: выбранный дубляж / оригинальный голос); **E2** тайм-аут бездействия диалога и английская команда остановки (рекомендуется настраиваемый тайм-аут 30 секунд и “Stop”); **E3** настройки инициативных сообщений и тихие часы (рекомендуется молчание до согласия при вводе в приложение, затем настроенные триггеры); **E4** определение отсутствия/звонков/игр (рекомендуются сигналы ОС/приложений под контролем пользователя и ручной тихий режим); **E5** обработка пропущенных напоминаний (рекомендуется одна сводка после возобновления, без повтора всех пропущенных голосовых уведомлений).

Критерии готовности: точность диалога и намерений задач на русском/английском; измерения ложных срабатываний/пропусков ключевой фразы; произвольные фразы; перебивание и эхоподавление; мгновенное отключение микрофона; работа области уведомлений/закрытого окна; сценарии тихих часов/звонка/игры; сквозные задержки CPU/памяти. Точные требуемые голосовые ресурсы и разрешения — условия выпуска, а не завершённая работа.

## 7. Направление F — интеграции, приватность и автономная подписка

Предложение по календарю: независимо полезный внутренний календарь и необязательные адаптеры Google Calendar/Outlook, OAuth через системный браузер, минимальные области доступа и защищённые Windows токены обновления. Синхронизировать изменения поставщика постепенно и хранить последнюю синхронизированную базу. При изменении одного события с обеих сторон сохранять версии и спрашивать пользователя. Отключённый адаптер не удаляет внутренние проекты, заметки или календарные данные.

При тайм-ауте после передачи запроса отправки письма поставщику результат остаётся неизвестным: до повторной отправки нужно свериться с поставщиком, а если это не даст ясности — спросить пользователя. Нельзя автоматически повторять отправку вслепую или сообщать как подтверждённый успех/отказ. Локальное намерение в очереди само по себе не доказывает доставку.

Решения: **F1** политика экспорта (рекомендация: выбранные календари и размещения задач; привычки приватны, пока пользователь не включит); **F2** поведение при внешнем удалении (рекомендация: спрашивать, если это удалит локальный элемент или конфликтует с более новой локальной работой); **F3** возможности Gmail (рекомендация: отдельные разрешения на чтение/поиск, черновик и отправку; без автоматического зеркалирования всей почты); **F4** поставщики поиска/погоды (рекомендация зависит от условий, доступности, атрибуции и цены; не выбраны). Интернет-поиск передаёт запрос, погода — только необходимый город; локальной языковой модели не требуется становиться облачной.

**F9** автономный режим без интернета — отдельный выбор. Рекомендация: все разрешённые локальные функции задач/привычек/календаря/заметок, локальный разговор и напоминания по срокам продолжают работать; синхронизация/поиск/погода показывают недоступность или состояние очереди, если уместно. Нельзя сообщать об успешной удалённой отправке, пока нет сети. По окончании автономного права действует отдельно утверждённая политика блокировки; отсутствие интернета не продлевает его.

Возможности файлов/устройства используют явно выбранные пути/приложения и видимые разрешения. Имя/никнейм и город поддерживаются как данные профиля; более широкая автоматически выведенная долговременная память не утверждена. Удаление локальной истории, отзыв токенов и состояние моделей/загрузок требуют отдельных элементов управления. Телеметрия по всему продукту не предполагается.

Предложение по автономному лицензированию: внешний процесс покупки выдаёт файл лицензии с привязкой к устройству и цифровой подписью; приложение локально проверяет встроенный открытый ключ. Закрытый ключ подписи хранить вне распространяемого приложения. Лицензия содержит продукт/функции, срок действия и привязку к устройству, без задач или разговоров. Продление импортирует новый подписанный файл. Это предложение процесса выдачи, не существующая система подписки/платежей и не новое разрешение на сервер активации.

Остаётся конфликт требований: ранее для подписки запрашивался аккаунт, позднее потребовалось полностью автономное право использования. **F5** выбрать локальный профиль и покупку лицензии-файла без обязательного аккаунта в приложении (рекомендация) либо аккаунт только у внешнего поставщика покупки, при этом приложение всё ещё проверяет файл автономно. Не добавлять молча собственный сервер активации. Цена, период продления, продавец/поставщик платежей, налоги и поддерживаемые страны покупки остаются коммерческими решениями, требующими фактической проверки; не обещать универсальную доступность платежей.

**F6** начало пробного периода: рекомендуется первое фактическое использование любой функции продукта, включая ручной планировщик; одни только экраны установки и ожидание загрузок не запускают семь дней. Альтернатива: дождаться всех требуемых моделей, оставив до этого только настройку. **F7** изменение часов/переустановка/смена устройства: рекомендуется подписанный срок действия, локальные верхние отметки времени и явный путь восстановления/повторной выдачи; полностью автономное ПО не может гарантировать уникальный пробный период для человека, защиту от переустановки или защищённые от подделки часы. Отпечаток устройства не доказывает, что это один и тот же человек. **F8** истёкший срок: функции продукта заблокированы, данные сохраняются как утверждено; рекомендуется оставить доступ к продлению/импорту, локальному удалению и автоматическим копиям, остановить фоновый захват и инициативную речь. Нужно явно решить, продолжает ли работать обслуживание копий.

Карточки выбора **F5**, **F6** и **F8** всё ещё ожидают ответа и не утверждены. Критерии готовности: рассмотренные области доступа/проверки поставщиков; отзыв учётных данных; двустороннее создание/изменение/удаление и конфликты повторов; тайм-аут поставщика/неизвестный исход отправки почты; автономная проверка подписи и продление; откат часов и восстановление после смены оборудования; истёкшее состояние без потери данных. Сейчас не создаются учётные данные, платёжный сервис или отпечаток устройства.

## 8. Направление G — установка, обновления и приёмка

Предлагаемый установщик отделяет подписанные пакеты приложения/среды выполнения от ресурсов моделей, подходящих устройству и загружаемых при первом запуске. Первичная настройка проверяет свободное место и совместимость, показывает понятный прогресс подготовки, продолжает прерванные загрузки, проверяет закреплённые хэши/подписанные манифесты и атомарно активирует полный набор ресурсов. Сохранять заведомо рабочий набор до проверки замены. Установка проходит автоматически, без консоли/ручных команд; нельзя создавать впечатление скрытых глобальных изменений системы.

**G1** архитектура Windows: рекомендуется сначала базовый x64, поддержку ARM64 решить отдельно; целевые версии продукта — Windows 10/11. **G2** обновления: рекомендуется уведомление и запланированный перезапуск приложения после резервной копии, с восстановлением; не принуждать к перезапуску во время речи или редактирования задач. **G3** пакет/распространение: сравнить самостоятельный подписанный установщик и магазин после оценки частных сред выполнения, автономных лицензий, ограничений оплаты и стоимости обновлений. Для фиксации цепочки технологий нужна таблица совместимости точных сборок Python/PostgreSQL, версий фреймворков и нативных зависимостей.

Предлагаемая матрица приёмки одновременно проверяет Flutter-эффекты, PostgreSQL, ожидание ключевой фразы, распознавание, LLM и TTS на устройстве Windows с CPU и 8 ГиБ. Фиксировать холодный/тёплый запуск, пиковую резидентную память, отзывчивость, задержку первого токена/аудио, занимаемое место и размер загрузки. Численные пороги выпуска нужно выбрать и измерить, а не выдумывать как достигнутые. Также проверить жизненный цикл Win10/11, прерванную установку, повреждённые ресурсы, нехватку места, отказ модели, миграцию/восстановление, дубли операций, изменение разрешений, сон/возобновление и освобождение микрофона.

Критерии готовности: воспроизводимые сборки пакета на чистых поддерживаемых системах; документированный список зависимостей/лицензий; проверка подписанных артефактов; продемонстрированное восстановление и сохранность данных; вводная справка на двух языках. Это будущие проверки. Эта задача документации не устанавливает зависимости и не создаёт установщик.

## 9. Направление H — Android и будущая синхронизация

Сохранять стабильные ID, версионированные контракты команд/чтения, именованные часовые пояса, сопоставления источников-поставщиков и явные типы конфликтов. API Windows держать за адаптерами. Flutter может повторно использовать UI, но нельзя считать, что Python-хост или сервер PostgreSQL без изменений заработает на Android.

**H1**, решение на будущее: локальная среда/хранилище Android, подключение к Windows-хосту пользователя или явно утверждённый облачный сервис. Каждый вариант влияет на офлайн-поведение, ограничения фонового микрофона, батарею, привязку пробного периода и синхронизацию. Сохранять запрошенное направление Android, не выбирая по умолчанию мобильную базу, сервер или новую политику облачных прав.

Будущая синхронизация передаёт логические записи и ревизии, а не файлы каталога данных PostgreSQL. До реализации определить идентификацию/восстановление аккаунта, шифрование передачи/хранения, разрешение конфликтов, распространение удаления и политику лицензии на несколько устройств. Синхронизация Google/Outlook календаря отличается от полной синхронизации Djarvis между устройствами.

Текущие критерии готовности: рассмотренные платформенно-независимые границы и описанные предположения для мобильной версии. Реализация Android и критерии приёмки синхронизации разрабатываются на отдельном согласованном этапе; план Windows не должен заявлять, что эти функции реализованы.

## 11. Основные технические источники

- [Поддерживаемые платформы Flutter](https://docs.flutter.dev/reference/supported-platforms): направление платформ; не доказательство производительности этого приложения при совместной нагрузке.
- [Python в Windows](https://docs.python.org/3/using/windows.html): распространение/встраивание приложения; точную версию и упаковку зависимостей ещё нужно проверить.
- [Установка Psycopg](https://www.psycopg.org/psycopg3/docs/basic/install.html): требования кандидата-драйвера к платформе.
- [Развёртывание FastAPI](https://fastapi.tiangolo.com/deployment/): кандидат на локальный API-хост, не выбран.
- [pg_ctl PostgreSQL](https://www.postgresql.org/docs/current/app-pg-ctl.html), [изоляция транзакций](https://www.postgresql.org/docs/current/transaction-iso.html), [pg_dump](https://www.postgresql.org/docs/current/app-pgdump.html), [типы даты/времени](https://www.postgresql.org/docs/current/datatype-datetime.html): процесс, параллельный доступ, дамп и ограничения часовых поясов.
- [llama.cpp](https://github.com/ggml-org/llama.cpp), [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx): кандидаты локальных сред вывода/речи; модели рассматриваются отдельно.

- [Карточка Qwen3-TTS Base](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-Base), [пример кода с поддержкой CPU](https://github.com/QwenLM/Qwen3-TTS/blob/main/qwen_tts/cli/demo.py): возможности кандидата на синтез речи; не базовая производительность или права на персонажей.
