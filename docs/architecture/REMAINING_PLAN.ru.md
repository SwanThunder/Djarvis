# План оставшегося проектирования и согласований

[English version](REMAINING_PLAN.md) · [Утверждённые решения](DECISIONS.ru.md) · [Подробный проект ядра планера](PLANNER_CORE.ru.md)

Дата: 2026-11-03. Статус: проектирование, не разрешение на реализацию. Документ описывает оставшиеся направления работы, не сокращая запрошенный объём продукта. Все рекомендации ниже остаются предложениями, пока владелец явно их не примет. Выбор версий, планы реализации и программирование требуют отдельного согласования.

## 1. Текущая основа и учёт решений

В репозитории есть каркас и двуязычные спецификации продукта, дизайна, архитектуры и планировщика. Работающего приложения, схемы базы данных или установщика нет. Языковая модель для разработки загружена и прошла краткую проверку запуска; это не проверенная производственная голосовая система и не измерение производительности CPU при 8 ГиБ. См. [оценку локальной модели](../LOCAL_MODEL.ru.md).

Утверждённые направления технологий: Flutter для UI (ADR-001), локальный PostgreSQL (ADR-002), Python для логики ядра/фонового процесса со средой выполнения под управлением приложения (ADR-003), управление приложением запуском/остановкой изолированного PostgreSQL без консоли (ADR-004). Автоматические локальные копии создаются ежедневно и перед изменением структуры/миграциями; срок хранения по умолчанию — семь дней, расписание и срок хранения настраиваются. Собственный сервер активации или хранилище пользовательских данных в облаке не утверждены.

Новые подтверждённые правила планировщика: каждый ввод явного крайнего срока только с датой требует запроса времени; дополнительные поля задач имеют общую настройку отображения и могут раскрываться отдельно в каждой задаче; неделя привычек начинается в понедельник, дни паузы исключаются из оценки, серия замораживается на паузе, исправления сохраняют историю. Это не превращает окно размещения плановой даты 06:00–22:00 в крайний срок.

Решения F5, F6 и F8 приняты: локальный профиль без обязательного аккаунта, импорт подписанного файла лицензии с автономной проверкой; семидневный пробный период начинается при первом использовании любой функции продукта, а не при установке или ожидании загрузки; по истечении срока функции планировщика/помощника блокируются, данные сохраняются, остаются доступны продление/импорт, удаление данных и автоматические копии. Любой захват микрофона и инициативная речь останавливаются. Согласованный объём зафиксирован в ADR-005; детали реализации остаются открытыми.

Также приняты D1 и D3: для создания задачи нужны название и явно заданный приоритет, остальные поля можно заполнить позже; ручное время начала без длительности — только маркер начала, перед автоматическим планированием нужно запросить длительность; для отсутствующей даты месяца в правиле повторения настраивается пропуск или последний день месяца (по умолчанию), при этом исходная точка отсчёта сохраняется.

Также приняты D4 и D5: если после паузы в гибкой неделе остаётся меньше доступных для оценки отдельных дней, чем требует неизменённая квота, неделя считается приостановленной — без пропуска и нарушения серии; фиксированная серия считается по успешным запланированным дням, гибкая — по успешным неделям. Исправления привычки допускаются для любой прошедшей даты в течение срока её существования; они сохраняют историю исправлений и пересчитываются с учётом цели, действовавшей на ту дату. Точные записи и механика пересчёта остаются предложениями.

D2 принят: у каждой привычки и личного повтора есть выбор — следовать местному времени или сохранять исходный фиксированный часовой пояс. Если выбор не задан, при смене часового пояса нужно спросить пользователя. Не применять это правило автоматически к событиям из внешних календарей и не переносить исторические записи; точные переходы DST и механика схемы остаются предложениями. D6 принят частично: выбранное вхождение разделённой задачи завершается только отдельным действием; в этом предложении действие сопоставлено с `CompleteOccurrence`. Отметки сегментов показывают только прогресс, отмечать все сегменты не требуется, а истёкшее время не доказывает выполнение. Автоматические перерывы требуют заданных пользователем длительности и частоты; до настройки обеих величин они не добавляются. Число сегментов, минимальная/максимальная длительность, сумма/распределение, буферы и обработка оставшихся размещённых сегментов после завершения остаются открытыми.

У каждого нерешённого решения ниже есть стабильный ID. Вопросы выдаются небольшими группами вариантов с выбором; интерфейс ответов также допускает свободный текст. Рекомендуемый или заранее выбранный вариант не считается принятым, пока владелец его не отправит. Неизвестные ответы из прежних пронумерованных сообщений нельзя восстанавливать догадками.

## 2. Направление A — ядро, процессы и контракты

Предлагаемая структура: Flutter отображает модели чтения; один Python-хост в пользовательском сеансе владеет командами, политиками, планированием, напоминаниями и очередями интеграций. Хост управляет собственной базой PostgreSQL и изолированными рабочими процессами моделей/речи. Закрытие окна оставляет хост и прослушивание ключевой фразы активными; «Полностью выйти» останавливает захват звука, рабочие процессы и частную базу. Повторный запуск приложения подключается к существующему хосту, а не открывает второй процесс-владелец каталога данных.

Правила предметной области и сценарии приложения не импортируют Flutter, фреймворки вывода моделей или SDK поставщиков. Предлагаемые модули Python: `domain`, `application`, `planning`, `storage`, `conversation`, `permissions`, `integrations` и `platform_windows`. Это логические границы, а не поручение создавать пакеты сейчас. Существующий каталог папок — каркас; сопоставить с ним модули можно после рассмотрения.

Рекомендуемый локальный транспорт: версионируемый HTTP API команд/запросов и поток событий WebSocket, привязанные только к loopback-интерфейсу и аутентифицируемые секретом на время запуска, переданным через защищённый локальный канал. Не помещать секрет в URL или журналы, не открывать слушатель для локальной сети и не выдавать UI учётные данные базы. FastAPI — кандидат, но не утверждённая зависимость. Альтернатива: именованные каналы Windows с ACL пользователя; это исключает слушающий HTTP-порт, но требует больше нативной работы и другого адаптера Android.

Предлагаемый конверт запроса: ID действия, версия контракта, ID/ревизии целей, типизированные данные и контекст разрешений. Состояния ответа различают уточнение, необходимость подтверждения, отказ, конфликт, локальное применение и постановку во внешнюю очередь. Подтверждение поставщика приходит отдельным последующим событием. События содержат ревизии; при переподключении клиент получает актуальную модель чтения, а не предполагает, что получил все временные события. Отмена генерации не означает отмену уже зафиксированного действия.

Неоднозначная цель или предполагаемая дата всегда требуют уточнения, даже если пользователь отключил подтверждения изменений задач. Уточнение определяет намерение; сохранённое разрешение не может угадывать, какую из нескольких встреч имеет в виду пользователь.

Речь пользователя, UI и запланированные предложения проходят через один и тот же шлюз команд. Модель получает узкие инструменты, а не произвольный SQL или выполнение команд оболочки. Результаты поиска, письма и содержимое файлов — недоверенные данные, они не могут выдавать разрешения. Пользователь выдаёт возможность в настройках, может отозвать её; перед выполнением разрешение проверяется повторно.

Решения: **A1** транспорт; **A2 — принято:** пользователь приложения может отдельно выдать запоминаемые и отзываемые разрешения не запрашивать подтверждение для создания, изменения, перемещения, завершения и удаления задач. Разрешение на удаление задачи никогда не разрешает удаление пользовательского файла. Неоднозначную цель всегда нужно уточнять; отправка писем и удаление/перезапись пользовательских файлов всегда требуют подтверждения; изменение цели/нагрузки привычки всегда требует принятия предложения. **A3 — принято частично:** отзываемое разрешение запускать выбранные пользователем приложения позволяет запускать их без повторного подтверждения. Оно не даёт общего доступа к SQL/оболочке/скриптам, произвольным аргументам, удалению/перезаписи файлов или обходу согласия ОС; точная идентификация приложения и API проверки аргументов остаются предложением. Завершение работы Windows, перезапуск Windows и выход из учётной записи всегда требуют отдельного подтверждения при каждом действии. Разрешения на задачи и Gmail это не отменяют. Эти действия отличаются от полного выхода из приложения и команды остановки диалога «Хватит»/“Stop”. Подтверждения для остальных действий с устройством остаются открытыми.

Критерии готовности (только будущие сценарии): отдельные сохранённые разрешения для категорий действий с задачами, отзыв до выполнения, удаление задачи без удаления файла, неоднозначная цель при отключённых подтверждениях, один общий переключатель Gmail для чтения/поиска/черновика/отправки и подтверждение точных данных каждого письма, обязательное подтверждение файлов, принятие изменения цели/нагрузки привычки, запуск выбранных приложений без повторного подтверждения, но без произвольных команд/аргументов или обхода согласия ОС, отзыв до запуска, подтверждение каждого завершения работы Windows/перезапуска/выхода из аккаунта, отсутствие обхода разрешениями задач/Gmail и отличие от полного выхода/«Хватит», отклонение устаревшего подтверждения, отзыв разрешения во время работы в очереди и восстановление после сбоя хоста/рабочего процесса. Программирование этих проверок ждёт согласования.

## 3. Направление B — локальный PostgreSQL, схема и восстановление

Рекомендуемое размещение: файлы среды выполнения под управлением приложения отдельно от постоянных данных пользователя и удаляемого кэша. Производственные пользовательские данные хранить в явно выбранном каталоге данных пользователя, не в исходном дереве или каталоге установки. PostgreSQL слушает только локально на управляемом свободном порту, использует отдельную роль базы и аутентифицированные соединения, не присваивает себе и не останавливает постороннюю установку. При запуске проверяются идентичность/версия кластера и отсутствие второго хоста, управляющего тем же кластером. Дистрибутив точных бинарных файлов и совместимость с Windows 10 требуют проверки.

Кандидат на драйвер — Psycopg 3 с ограниченным пулом соединений и короткими транзакциями. Выбрать совместимые сочетания Python/PostgreSQL/драйвера и упаковать вместе; пользовательскому сценарию не нужны глобальный Python, ручной pip, Docker или видимая консоль. Встроенный дистрибутив Python — возможный способ упаковки; замороженные исполняемые файлы — альтернатива для сравнения с нативными зависимостями речи/драйвера. Точные версии и способ упаковки не выбраны.

[Проект ядра](PLANNER_CORE.ru.md) описывает логическую схему: задачи/шаблоны, устойчивые вхождения повторов, размещения, проекты, привычки и измерения, события календаря/сопоставления поставщиков, заметки, напоминания/доставки, разрешения с ограниченной областью, действия/аудит/исходящая очередь, срок хранения разговоров и ревизии планирования. Следующее рассмотрение схемы должно определить столбцы, ограничения, внешние ключи, политику удаления, индексы и миграции. Идентичность вхождения задачи должна быть отдельна от перемещаемого размещения и необязательного срока. Именованный часовой пояс хранить отдельно от UTC-моментов.

Рекомендация по конкурентному доступу: каждая запись, влияющая на планирование, включая синхронизацию календаря, использует одну и ту же короткую блокировку планирования для профиля и увеличивает ревизию. Принятие плана захватывает блокировку, повторно проверяет входные данные и записывает изменения атомарно. Блокировка базы не должна удерживаться в ожидании пользователя, вывода модели или сети. Изменение строки, не влияющее на план, не обязано делать предложение дня недействительным.

Процесс резервного копирования: создать согласованный дамп базы и манифест вложений; сохранять неизменяемое содержимое ссылочных вложений, пока копия создаётся; проверить архив и восстановить его в изолированную временную базу до заявления о возможности восстановления. Не копировать работающий каталог данных PostgreSQL как обычную резервную копию приложения. Удалять старые копии только после успешной проверки новой. В обычные резервные копии планировщика не включать веса моделей, удаляемый кэш и секреты OAuth.

Процесс миграции: проверить свободное место и версии, создать необходимую восстанавливаемую копию, остановить несовместимые процессы, применить версионируемую миграцию, проверить ограничения и перезапустить ядро. При неудачном обновлении сохранить путь восстановления. Откат одних бинарных файлов недостаточен после несовместимого изменения схемы; крупные обновления PostgreSQL требуют отдельной рассмотренной процедуры миграции.

Решения: **B1 — принято:** использовать отдельную настраиваемую локальную папку копий приложения вне рабочей базы PostgreSQL; точный путь не выбран. **B2 — принято:** защищать ключ копии средствами Windows, без отдельного пароля и дополнительного ключа восстановления. Точные шифр/KDF, API/флаги защиты, область/хранение/ротация ключа, формат архива/миграции и механика восстановления после ошибки остаются открытыми. Не обещать переносимость или восстановление при недоступности защищённого ключа и не утверждать, что копия всегда работает только на том же компьютере. **B3 — политика принята, детали реализации открыты:** автоматические копии включают историю разговоров. Полный снимок восстанавливается только после предварительного просмотра и копирования текущих данных; выборочное восстановление не выбрано. Восстанавливаются только данные в пределах архива, не лицензия/пробный период, учётные данные OAuth или образ Windows. Автоматическое истечение истории старше 30 дней не переписывает архивы; она остаётся в архиве до его истечения по собственному сроку хранения (по умолчанию семь дней). При восстановлении применяется текущий целевой срок хранения истории, а не прежняя политика архива. При явном удалении истории показывать затронутые копии и предлагать пересоздание или удаление после явного подтверждения пользователя; не удалять молча все пользовательские файлы. Различать ручное удаление и истечение срока; не заявлять о физическом стирании истории из всех копий через 30 дней, полном стирании до обработки архивов, молчаливом возвращении истории, физическом стирании или контроле внешних копий. Доступность/формат архивов, откат и действия при ожидающей/недоступной копии остаются открытыми. Не включать секреты и веса моделей в обычные резервные копии.

Критерии готовности (только будущие сценарии): рассмотрение SQL-схемы; сценарии перезапуска/сбоя/нехватки места; отсутствие конфликта владения кластером между процессами; предварительный просмотр полного снимка и копирование текущих данных; исключение лицензии/пробного периода, учётных данных OAuth и образа Windows из области архива; поведение при недоступном защищённом ключе без обещаний переносимости/восстановления; успешное восстановление с вложениями; восстановление после неудачной миграции; семидневный срок хранения архива; история включена в копии; истечение срока истории не переписывает архив до его собственного истечения; восстановление применяет текущий целевой срок истории; ручное удаление предлагает действия с затронутыми копиями после подтверждения; нет обещания стирания из всех копий за 30 дней, преждевременного полного стирания или молчаливого возврата истории; доступность/откат архива и обработка ожидающих/недоступных копий. В рамках этой задачи проектирования база не устанавливается и не инициализируется.

## 4. Направление C — экраны и обязательный визуальный дизайн

[Визуальная спецификация владельца](../DESIGN.ru.md) остаётся обязательной: тёмный Glassmorphism/Bento, узкая левая боковая панель, контекстная верхняя панель с поиском и профилем/действиями, футуристическая круговая визуализация помощника над панелью дня, без фонового изображения. Должны работать все три точные палитры и независимые режимы Glass/Solid, включая непрозрачные вложенные поверхности Solid.

Предлагаемая навигация: Сегодня, Задачи, Календарь, Привычки, Проекты, Заметки, Разговор, Настройки. Экран «Сегодня» содержит помощника, текущий/следующий блок, остаток плана дня и прогресс привычек. Нераспределённая работа и предупреждения о сроках явно отличаются от блоков с заданным временем. Предварительный просмотр команды подсвечивает, какие именно записи будут изменены. При конфликте календаря отображаются обе версии и последствия выбора каждой.

Разделы настроек: оформление; планирование и доступное время; привычки; голос/персонаж/микрофон; инициативные сообщения/тихие часы; подключения и возможности; локальные данные/история/копии; модели/загрузки; подписка. Глобальный поиск сначала ищет среди разрешённых локальных записей; интернет-поиск запускается как явное действие помощника. Для пустого экрана, загрузки, офлайн-состояния, отказа в разрешении, конфликта, подготовки модели и истечения лицензии нужны настоящие макеты, а не вымышленные демонстрационные данные.

Решения: **C1** начальная палитра/материал (предложено `deep-blue-pink` + Glass); **C2** плотность и вид дня по умолчанию (рекомендация: комфортная плотность, временная шкала с компактными карточками дел/привычек); **C3** нужен ли отдельный полноэкранный раздел «Разговор» наряду с панелью помощника. Отображение дополнительных полей уже выбрано; скрытые поля сохраняют данные.

Критерии готовности: рассмотренная карта экранов/состояний и нефункциональные макеты до программирования UI; шесть сочетаний темы и материала; клавиатура/фокус/уменьшение движения; читаемое масштабирование; фактические измерения контраста и проверка эффектов вместе с голосовым стеком на базовом устройстве. Не менять молча утверждённое предпочтение Glass только потому, что устройство работает медленно.

## 5. Направление D — семантика планировщика и привычек

Подтверждённые правила записаны в [PRODUCT](../PRODUCT.ru.md) и [PLANNER_CORE](PLANNER_CORE.ru.md): четыре приоритета; раздельные просрочка крайнего срока и пропуск размещения, без автоматического изменения даты пропущенного размещения; запрос недостающей длительности до автоматического планирования; блокировка размещения, заданного вручную; согласие на разделение отдельно для каждой задачи и отдельное действие завершения выбранного вхождения; повторение от исходной точки с отдельными незавершёнными вхождениями; выбор часового пояса для каждой привычки/личного повтора; четыре типа привычек; расписания по фиксированным дням и гибкая частота по разным успешным дням; пропуски привычек не становятся долгом задач.

Подтверждённое создание задачи: обязательны название и явно заданный приоритет; если приоритет не указан, нужно спросить его, а не выбирать молча обычный. Остальные поля можно заполнить позже, если их не требует запрошенная операция. Для плановой даты только с датой используется 06:00–22:00; при вводе крайнего срока без времени всегда задаётся вопрос о времени. Ручное время начала без известной длительности отображается видимым маркером начала, а не проверенным занятым интервалом. Перед автоматическим планированием нужно запросить длительность; нельзя молча считать неизвестное время окончания свободным. Возможность исключить маркер из конкретной попытки планирования остаётся предложением по UX. Автоматический планировщик не придумывает длительность и не меняет срок молча.

Предлагаемый алгоритм: получить ревизию планирования; собрать доступность, заблокированные встречи/блоки и правила перерывов; запросить недостающие обязательные данные; построить допустимые размещения; отдавать предпочтение срокам и приоритетам, соблюдая явные блокировки; объяснить нераспределённую работу и нехватку времени; показать изменения; применить их только с требуемым подтверждением/разрешением и повторной проверкой ревизий. Автоматические перерывы добавляются только после настройки пользователем и длительности, и частоты; до этого их нет. Это не заявление о глобально оптимальном плане. UI должен отличать срок, который нельзя соблюсти, от просто перегруженного предпочтительного окна.

При рассмотрении повторов охватить дневные/недельные/месячные схемы, интервальные точки отсчёта, исключения, изменения одного вхождения или его и последующих, отмену без удаления исторического долга. Подтверждено: для отсутствующей даты месяца у каждого правила повтора настраивается политика — последний день месяца или пропуск; по умолчанию используется последний день. Исходная точка отсчёта сохраняется: 31 января 2027 → 28 февраля → 31 марта, а не 28 марта. У каждой привычки и личного повтора также выбирается следование местному времени или сохранение исходного фиксированного часового пояса; при смене пояса, если выбор не задан, нужно спросить. Не переносить по этому правилу внешние события или исторические записи. В спецификации времени остаётся определить точную обработку DST, события на весь день и с заданным временем, а также нормализацию занятости/свободного времени.

Модель привычек: отдельные дневные измерения, оцениваемый день/период, история версий цели и исправленные записи. Пауза исключает дни паузы из оценки и замораживает серию. Подтверждено: если после паузы в гибкой неделе остаётся меньше доступных для оценки отдельных дней, чем требует неизменённая квота, неделя считается приостановленной — без пропуска или нарушения серии. Фиксированная серия считает подряд идущие успешные запланированные дни; гибкая — подряд идущие успешные недели, приостановленные недели замораживают серию. Исправления допускаются для любой прошедшей даты в течение срока существования привычки; нужно сохранять историю исправлений и пересчитывать результат с учётом цели, действовавшей на ту дату. Точные записи и механика пересчёта остаются предложениями. Для воздержания нужна явная отметка успеха; молчание не доказывает успех. Предложения изменить цель/нагрузку никогда не применяются автоматически.

Решения: **D1 — принято:** обязательные название и явно заданный приоритет, остальные поля необязательны, маркер только времени начала и запрос длительности перед автоматическим планированием; **D2 — принято:** у каждой привычки/личного повтора есть выбор местного времени или исходного фиксированного пояса; при смене часового пояса и отсутствии выбора нужно спросить, не переносить по умолчанию внешние/исторические события; точные переходы/хранение открыты; **D3 — принято:** политика отсутствующей даты месяца настраивается для каждого правила повтора, по умолчанию последний день месяца, альтернативный вариант — пропустить, исходная точка отсчёта сохраняется; **D4 — принято:** неделя с недостаточным числом доступных для оценки дней после паузы считается приостановленной; серия фиксированной привычки — по успешным запланированным дням, гибкой — по успешным неделям; **D5 — принято:** исправления для любой прошедшей даты в течение срока существования привычки, с сохранением истории и пересчётом по исторической цели; **D6 — принято частично:** выбранное вхождение задачи завершается только отдельным пользовательским действием, в этом предложении сопоставленным с `CompleteOccurrence` (точное имя API не утверждено); отметки сегментов — только прогресс, все отмечать не требуется, истёкшее время не доказывает выполнение; автоматические перерывы добавляются только после настройки пользователем длительности и частоты. Открыты число/минимальная/максимальная длительность/сумма/распределение сегментов, буферы и действия с оставшимися размещёнными сегментами.

Критерии готовности: разобранные примеры плановой даты без времени и уточнения срока; несколько просроченных вхождений повтора; позднее выполнение без сдвига графика; выбор следования местному времени/исходному поясу при поездке и уточнение при отсутствии выбора; пропуски/повторы DST; невозможные планы; устаревшие предложения; отметки всех сегментов без автозавершения до отдельного действия для `CompleteOccurrence`; отсутствие автоматических перерывов, если не задана частота или длительность; недели с паузой/исправления/воздержание. Это будущие сценарии, а не выполненные испытания; алгоритм и схема не запускались.

## 6. Направление E — локальный разговор, речь и персонажи

Предлагаемая цепочка: захват микрофона → локальный детектор ключевой фразы/VAD → локальное распознавание речи → намерение/контекст → локальная языковая модель → команды под управлением политик или ответ → локальный синтез речи. Обнаружение перебивания должно работать во время озвучивания; отключение микрофона прекращает любой захват, включая обнаружение ключевой фразы. По умолчанию предлагается не хранить исходное аудио. История разговора остаётся настраиваемой пользователем, удаляемой и необязательной; временные буферы сессии и минимальный аудит действий не должны становиться скрытой стенограммой.

Бюджеты ресурсов должны учитывать Python-хост, PostgreSQL, UI и рабочие процессы речи/моделей вместе. Кандидаты небольших LLM и загрузка рабочих процессов по требованию требуют измерений точности/задержки. Одновременное хранение нескольких крупных моделей в памяти — не проверенная стратегия для 8 ГиБ; выгрузка рабочих процессов не должна ломать перебивание или фоновое ожидание ключевой фразы. Оценённая модель 4B для разработки ещё не выбрана как базовая производственная модель.

Кандидаты сред выполнения: llama.cpp для языкового вывода и sherpa-onnx для автономных речевых компонентов. Лицензии моделей проверяются отдельно от лицензий сред выполнения. Поддержка обнаружения ключевых слов не доказывает точное распознавание любой введённой пользователем фразы; произвольные фразы требуют обучения/проверки и явного ответа о неподдерживаемой фразе, а не притворства, что она принята.

Каталог моделей sherpa-onnx содержит варианты ASR для русского и английского языков; лицензия Apache-2.0 среды выполнения не определяет лицензии конкретных весов. Для как минимум одного старого пакета GigaAM на русском указаны некоммерческие условия, поэтому ни один выпуск GigaAM не утверждён для этого коммерческого продукта без проверки конкретного артефакта. Документированные предварительно обученные модели ключевых слов не подтверждают поддержку пользовательской русской фразы. Qwen3-TTS 0.6B Base — кандидат для оценки клонирования речи с русским/английским языками и условиями Apache-2.0 в карточке модели; варианты работы на CPU не являются официальным тестом задержки/памяти на Windows с 8 ГиБ. Ни один кандидат не выбран для выпуска.

Запрошенные личности Джарвиса, Рика Санчеза и Себастьяна и узнаваемые голоса остаются требованиями. Локальный MP3 Рика — ориентир, а не доказательство разрешения или готовая производственная модель голоса. До выбора ресурсов определить точную версию дубляжа/языка и получить необходимые разрешения на коммерческое использование. Лицензия ПО/весов речевой модели не даёт прав на персонажа или запись. Молча выбирать обобщённую замену нельзя. Для технических оценок можно применять надлежащим образом лицензированные нейтральные тестовые аудиоматериалы, не объявляя запрошенные производственные голоса готовыми.

Предлагаемые состояния помощника: микрофон выключен, ожидание ключевой фразы, слушает, обрабатывает, говорит, готовит модели, ограниченный режим/ошибка. Состояние видно в главном окне и области уведомлений. «Хватит»/“Stop” завершает диалог и возвращает к ожиданию ключевой фразы, если микрофон не отключён, доступ действует и необходимые локальные ресурсы доступны. Прерванный голосовой ответ не возобновляется автоматически поверх следующей реплики пользователя.

Решения: **E1** точная версия голоса/языка (Рик: предоставленный образец / другая лицензированная версия; Джарвис и Себастьян: выбранный дубляж / оригинальный голос); **E2 — принято:** после каждого ответа помощник по умолчанию ждёт 30 секунд следующую реплику пользователя; интервал настраивается и не ограничивает активную речь пользователя, вывод модели или TTS. «Хватит»/“Stop” завершает диалог и возвращает к ожиданию ключевой фразы, если микрофон не отключён, доступ действует и необходимые локальные ресурсы доступны; **E3 — политика принята, часть деталей открыта:** при первом запуске предложить настроить инициативное поведение; пока пользователь не выберет вариант, инициативная речь выключена, а пропуск не считается согласием. Ответы по запросу пользователя продолжают работать. Нужно спросить расписание тихих часов по местному времени или явный выбор «без тихих часов»; значение по умолчанию не подразумевается. Тихие часы подавляют инициативную речь с переходом на обычные уведомления ОС, если они разрешены, не отключая микрофон и не меняя разговор по запросу пользователя. Точное время/реализация открыты; **E4 — подход принят, реализация открыта:** для подавления при звонках/играх используются системные эвристики, выбранный пользователем список приложений и ручной тихий режим. Они не гарантируют обнаружение каждого звонка/игры. Если включён триггер возвращения после отсутствия, по умолчанию использовать 30 минут без ввода с клавиатуры/мыши в интерактивном сеансе; порог настраивается. Это не доказывает физическое отсутствие, не является глобальным мониторингом ввода ОС и не включает триггер автоматически. Тихий режим/звонки/игры подавляют инициативную речь с обычными уведомлениями ОС при наличии разрешения, не отключая микрофон и не меняя разговор по запросу пользователя. Детали детекторов, ограничения повторов и обработки в рабочем процессе открыты; **E5 — принято:** после сна/перезапуска предоставить одну сводку пропущенных напоминаний при действующем доступе и разрешении уведомлений ОС. Озвучивать её только если позволяют настройки инициативной речи, тихие часы, звонки/игры и текущий контекст; иначе показать обычное уведомление. Исключать устаревшие, отменённые и завершённые цели. Максимальная частота и точная механика доставки остаются открытыми.

Ограничения сигналов E4: состояние уведомлений Windows может отражать полноэкранную работу или презентацию, но не определяет каждую игру. Активные аудиосессии сами по себе не подтверждают, что идёт звонок. `GetLastInputInfo` сообщает о вводе в интерактивном сеансе, но не подтверждает физическое отсутствие. Пользователь выбрал сочетание эвристик + списка выбранных приложений + ручного тихого режима, но не реализацию или технологический стек детекторов.

Критерии готовности (только будущие сценарии): точность диалога и намерений задач на русском/английском; измерения ложных срабатываний/пропусков ключевой фразы; произвольные фразы; перебивание и эхоподавление; настраиваемый триггер 30 минут без ввода в интерактивном сеансе только при включённом возвращении после отсутствия; без вывода о физическом отсутствии/глобальном мониторинге; выбранный список приложений и ручной тихий режим; расписание тихих часов или явное отсутствие тихих часов; подавление инициативной речи без отключения микрофона и изменения разговора по запросу; обычное уведомление при разрешении ОС; настраиваемое 30-секундное ожидание после ответа без ограничения активной речи/вывода/TTS; возврат к ожиданию ключевой фразы по команде завершения; отключение микрофона на сеанс с возобновлением после настоящего перезапуска приложения/Windows; повторное открытие окна без перезапуска хоста; отсутствие захвата при истёкшем доступе или запрете ОС; видимость текущего состояния; выключенная инициатива при пропуске настройки; работа области уведомлений/закрытого окна; сценарии тихих часов/звонка/игры; сквозные задержки CPU/памяти. Точные требуемые голосовые ресурсы и разрешения — условия выпуска, а не завершённая работа.

**E6 — принято:** ручное отключение микрофона действует только в течение текущего сеанса приложения. После настоящего перезапуска приложения или Windows ожидание ключевой фразы возобновляется, если это разрешает Windows и действуют доступ/ресурсы; захват запрещён при истёкшем доступе или запрете микрофона со стороны ОС. Повторное открытие главного окна при работающем хосте не является перезапуском приложения. Полный выход останавливает рабочие процессы и захват до следующего разрешённого запуска. Учитывать системное/аппаратное отключение. Текущее состояние показывается в главном окне и области уведомлений; точные надписи и реализация остаются проектными.

**E7 — принято:** локальная история разговоров по умолчанию хранится 30 дней; пользователь может изменить срок, отключить историю или удалить её целиком. Политика B3: истечение срока не переписывает архивы; просроченная история остаётся в архиве до его истечения по отдельному сроку хранения, по умолчанию семь дней. При восстановлении действует текущий целевой срок хранения. Доступность архивов и детали отката остаются открытыми.

## 7. Направление F — интеграции, приватность и автономная подписка

Предложение по календарю: независимо полезный внутренний календарь и необязательные адаптеры Google Calendar/Outlook, OAuth через системный браузер, минимальные области доступа и защищённые Windows токены обновления. Не входят Google Tasks API, синхронизация заметок/проектов/вложений/почты и экспорт всех календарей. Синхронизировать изменения поставщика постепенно и хранить последнюю синхронизированную базу. При изменении одного события с обеих сторон сохранять версии и спрашивать пользователя. Если поставщик удалил событие, не менявшееся локально после последней синхронизации, спросить перед удалением локальной записи. Удаление экспортированного блока не удаляет автоматически задачу или привычку. Точные проекции и сопоставление изменений открыты. Отключённый адаптер не удаляет внутренние проекты, заметки или календарные данные.

При тайм-ауте после передачи запроса отправки письма поставщику результат остаётся неизвестным: до повторной отправки нужно свериться с поставщиком, а если это не даст ясности — спросить пользователя. Нельзя автоматически повторять отправку вслепую или сообщать как подтверждённый успех/отказ. Локальное намерение в очереди само по себе не доказывает доставку.

Решения: **F1 — политика принята, детали сопоставления открыты:** синхронизируются выбранные пользователем события календаря и временные блоки задач; для привычек требуется отдельное согласие, по умолчанию выключено. Не входят Google Tasks API, синхронизация заметок/проектов/вложений/почты и экспорт всех календарей. **F2 — политика принята, механика открыта:** перед локальным удалением спросить, если поставщик удалил событие, не изменявшееся локально после последней синхронизации; если изменили обе стороны, обязателен выбор пользователя по уже установленному правилу конфликта. Удаление экспортированного блока не удаляет автоматически задачу или привычку. **F3 — принято:** один общий переключатель разрешения Gmail объединяет чтение/поиск, черновики и отправку; каждая отправка требует подтверждения точных получателей, текста и вложений. Минимальные области OAuth, точные SDK/кэш и проверка поставщика остаются открытыми; нет широкого администрирования почты или молчаливого зеркалирования всего ящика. **F4** поставщики поиска/погоды (рекомендация зависит от условий, доступности, атрибуции и цены; не выбраны). Интернет-поиск передаёт запрос, погода — только необходимый город; локальной языковой модели не требуется становиться облачной.

**F9 — принято:** при действующем пробном периоде/лицензии и наличии необходимых локальных ресурсов все локальные разделы, напоминания, голос и разговор работают без интернета. Поиск, актуальная погода и внешние поставщики требуют сети. Локальное намерение в очереди не означает удалённое выполнение; нельзя подразумевать автоматический повтор при неизвестном результате отправки письма или вводить собственный сервер. Отсутствие интернета не меняет срок окончания автономного права.

Возможности файлов/устройства используют явно выбранные пути/приложения и видимые разрешения. Имя/никнейм и город поддерживаются как данные профиля; более широкая автоматически выведенная долговременная память не утверждена. Удаление локальной истории, отзыв токенов и состояние моделей/загрузок требуют отдельных элементов управления. Телеметрия по всему продукту не предполагается.

Утверждённое направление лицензирования: покупатель импортирует подписанный файл лицензии, а приложение проверяет его автономно; продление/импорт остаётся доступным при блокировке платных функций. Предлагаемая техническая реализация: файл подписывает внешний издатель, приложение содержит только материал для проверки, закрытый ключ подписи никогда не включается в поставку. Точный формат файла, алгоритм подписи, срок/правило привязки к устройству и процесс покупки/выдачи ещё предстоит спроектировать. Это не существующая платёжная система и не разрешение на сервер активации.

**F5 — принято:** локальный профиль и покупка лицензии-файла без обязательного аккаунта. Это заменяет прежнее требование иметь аккаунт для получения подписки. Будущая облачная идентификация/синхронизация — отдельный вопрос проектирования. Собственный сервер активации не добавляется. Цена, периоды продления, продавец/поставщик платежей, налоги и поддерживаемые страны покупки остаются коммерческими решениями, требующими фактической проверки; не обещать универсальную доступность платежей.

**F6 — принято:** семидневный пробный период начинается при первом фактическом использовании любой функции продукта, включая ручной планировщик. Экраны установки и ожидание загрузки сами по себе не запускают его; использование планировщика до завершения загрузки моделей запускает. **F7 — открыто:** изменение часов/переустановка/смена устройства; рекомендуется подписанный срок действия, локальные верхние отметки времени и явный путь восстановления/повторной выдачи. Полностью автономное ПО не может гарантировать уникальный пробный период для человека, защиту от переустановки или неподделываемые часы. Не считать отпечаток устройства доказательством, что это один и тот же человек. **F8 — принято:** функции планировщика/помощника блокируются, данные сохраняются; продление/импорт, удаление пользовательских данных и автоматические копии остаются доступны. Любой захват микрофона, включая ожидание ключевой фразы, и инициативная речь останавливаются. Разрешение на обслуживание резервных копий не означает разрешение продолжать работу помощника или других платных команд.

Карточки выбора **F5**, **F6** и **F8** отправлены и приняты 2026-11-03; технические/коммерческие детали за пределами их объёма остаются открытыми.
