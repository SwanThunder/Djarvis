# Разбор брифа компоновки главного экрана

[English version](DASHBOARD_LAYOUT_REVIEW.md) · [Обязательный дизайн](../DESIGN.ru.md) · [Описание продукта](../PRODUCT.ru.md) · [Проект поставки CP17](DELIVERY_DESIGN.ru.md)

Статус: разбор подготовлен в PLAN-016 и завершён в PLAN-017 (2026-11-04, Europe/Moscow). Ответы владельца, записанные ниже (L1–L4, L2a, L6, L7), — принятые продуктовые решения; всё остальное в документе — предложения или открытые вопросы. Экранов, прототипов и визуальных проверок нет; программирование не разрешено.

## 1. Источник

- Локальный оригинал: `design/Djarvis_Main_Dashboard_Layout_Architecture_v1_0.txt` (спецификация компоновки v1.0, на русском), SHA-256 `b8a782015dfa3434dda0f02e500e0d6c2224a41221847d2e6b2d1e0bf27aaa0d`. Он остаётся локальным, неизменным и исключённым из публикации, как и остальные дизайн-оригиналы владельца.
- Охват брифа: пространственное расположение главного экрана, иерархия контейнеров, адаптивная перестановка, граница между главным экраном и голосовым дворецким и обязательная плавающая кнопка микрофона, которую можно скрыть. Цвета, материалы, анимации, данные, API и бизнес-логику он явно не задаёт; их по-прежнему определяют [DESIGN](../DESIGN.ru.md) и визуальный бриф v2.1.
- Бриф сам указывает, что не заменяет архитектуру проекта, что геометрия референса не должна порождать новые разделы или фиктивные данные, а неразрешимые конфликты решаются в пользу архитектуры проекта с явным сообщением.

## 3. Что совпадает с текущим дизайном

- Узкая левая боковая панель, верхняя строка и адаптивная Bento-область; логотип вверху боковой панели.
- Группы верхней строки: контекст слева, поиск по центру, действия/профиль справа. Элемент профиля соответствует локальному профилю; требование аккаунта не появляется.
- Запрет CRM-содержимого, демо-записей, декоративных KPI и разделов только ради оформления.
- Единый раздел настроек: переключатель видимости кнопки микрофона входит в существующие настройки оформления, отдельная страница брифом запрещена.
- Адаптивность desktop/планшет/мобильный с неизменным функциональным порядком; Android остаётся будущим проектом, поэтому мобильные правила — ориентир.
- Цвета, материалы Glass/Solid и анимации остаются в DESIGN и v2.1; бриф их не добавляет.

## 4. Конфликты и пробелы с ответами владельца

| ID | Тема | Наблюдение | Решение |
| --- | --- | --- | --- |
| L1 | Круг ассистента | DESIGN требует круговой образ помощника над панелью дня; в сетке брифа круга нет, дворецкий вынесен в overlay. | **Выбор владельца:** круг остаётся вверху главного экрана над сеткой брифа. Сетка становится панелью дня. Overlay открывается для активной голосовой сессии. |
| L2 | Плавающая кнопка и mute | В продукте уже обязательна мгновенная кнопка выключения микрофона, прекращающая захват и для wake-фразы, и для диалога. Кнопка брифа вызывает дворецкого. | **Выбор владельца:** одна кнопка, два действия — основное нажатие вызывает дворецкого, дополнительное действие выключает/включает микрофон. Точный жест дополнительного действия открыт (L2a). |
| L3 | Действие при нажатии | Бриф говорит «открыть существующий интерфейс дворецкого»; в продукте вызов был только wake-фразой. | **Выбор владельца:** нажатие открывает overlay и сразу начинает слушать, как будто wake-фраза произнесена. Все условия захвата микрофона продолжают действовать. |
| L4 | Недоступное состояние | Истёкший доступ, запрет микрофона в Windows, отсутствие локальных ресурсов и ручной mute запрещают захват. | **Выбор владельца:** кнопка остаётся видимой в отдельном неактивном состоянии; нажатие показывает краткую причину и действие для исправления. Захват при невыполненном условии не происходит. |
| L5 | Ширина боковой панели | Бриф: ≈1/11–1/12 панели, уточнить по сетке проекта; DESIGN: 52–68 px. | Предложение: сохранить 52–68 px из DESIGN; бриф прямо отсылает к сетке проекта. |
| L6 | Содержимое верхней строки | У селектора контекста, плюса и уведомлений пока нет определённой функции в Djarvis. | **Выбор владельца (PLAN-017):** выбор дня, быстрое создание (задача, привычка, заметка) и список уведомлений (напоминания и ожидающие подтверждения); элемента профиля нет. |
| L7 | Содержимое карточек | Бриф задаёт только геометрию; предлагаемый первый экран DESIGN — круг, сводка дня, встречи/задачи, состояние привычек. | **Выбор владельца (PLAN-017):** соответствие из раздела 6 принято как есть, кроме строки профиля в верхней строке. |

### 4.1 Следствия L2–L4 (предложения на основе принятых правил)

- **Mute должен оставаться доступным при скрытой кнопке.** Продукт требует мгновенного выключения микрофона; скрытие плавающей кнопки не может его убрать. Предложение: дублировать mute в overlay дворецкого и в меню трея; новых маршрутов это не добавляет.
- **Дополнительное действие должно быть доступным (L2a).** Одно только долгое нажатие не мгновенно и недоступно с клавиатуры. Предложение: долгое нажатие или правый клик плюс доступное с клавиатуры контекстное меню той же кнопки, с видимым состоянием «выключен». **Выбор владельца (PLAN-017):** правый клик или клавиша меню открывает меню с выключением/включением микрофона. Глобальное сочетание клавиш не придумывается.
- **Состояние mute:** основное нажатие не включает микрофон молча. Показывается «Микрофон выключен» с явным действием «Включить», что согласуется с явным включением в схеме состояний звука (CP09).
- **Нажатие и условия:** каждое нажатие заново проверяет доступ, разрешение Windows и локальные ресурсы в момент начала захвата; нажатие во время активной сессии переводит фокус в существующий overlay, а не открывает второй. Голосовое использование считается использованием продукта для старта триала (ADR-005).
- **Истёкший доступ:** кнопка в неактивном состоянии ведёт к продлению/импорту лицензии; функциональный ассистент не открывается.
- **Тихие часы, звонки и игры** подавляют только проактивную речь; явное нажатие пользователя работает.
- Overlay — отображение существующей голосовой сессии (CP09/CP17), а не второй дворецкий; закрытие возвращает к сохранённому главному экрану. Круг на главном экране может показывать реальное состояние сессии без постоянной декоративной анимации (DESIGN).

| Верхняя строка — селектор контекста | Выбор даты/дня для раздела «Сегодня» (существующая сводка дня); альтернатива — не показывать до согласования. |

| Верхняя строка — уведомления | Список существующих напоминаний и ожидающих подтверждений; не показывать, если внутренний список уведомлений не утверждён. |

| Круг ассистента | Над сеткой; отражает реальное состояние сессии (ожидание wake-фразы, слушает, думает, говорит, mute, недоступен). |
| Верхние карточки 1–4 | Элементы сводки дня из существующего снимка дня, например запланированные на сегодня задачи, просроченные задачи, привычки на сегодня, ближайшее событие календаря. Это количества/списки существующих записей, а не новые KPI. |

| Крупная карточка — прогресс | Круговой прогресс привычек на сегодня; две строки — выполнение плана дня и уже определённые планировщиком индикаторы просрочки/пропущенного времени. |
| Правая верхняя карточка | Просмотр предложения плана дня (три сегмента: утро/день/вечер) — только предложение. |
| Правая нижняя карточка | Два ближайших пункта (встречи или размещённые задачи) со статусом. |
