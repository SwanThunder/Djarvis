## 3. Как проверена сама структура

- **Покрытие требований.** Каждая обязательная функция из PRODUCT сопоставлена с таблицами схемы, командами API и модулем (§5). Непокрытых функций нет.
- **Схема.** Весь SQL из SCHEMA выполнен во временном кластере PostgreSQL 18: 63 инструкции, 45 таблиц, ошибок нет. Кластер удалён. Отдельно проверено, что база сама отклоняет нарушения правил продукта: задача без приоритета, срок без времени, второе вхождение разовой задачи, второй запущенный таймер, блок с концом раньше начала, разрешение на удаление файлов, повтор одной отметки привычки. Все 13 случаев повели себя как задумано.
- **Согласованность.** Имена команд в API совпадают с именами в схеме и модулях; ссылки между документами проверены; обе языковые версии сверены по структуре.
- **Чего эта проверка не доказывает:** что программа будет работать. Это покажут тесты по фазам и реальные проверки после программирования.

## 6. Технические правила, зафиксированные этим отчётом

Мелкие правила, которые раньше числились открытыми в CP05–CP07 и теперь закрыты на уровне структуры (меняются только по согласованию):

1. Равенство в автоплане: при одинаковых сроке и приоритете раньше идёт задача, созданная раньше (порядок `uuidv7`). План детерминирован.
2. Вхождения повторяющихся задач создаются на 60 дней вперёд; курсор `generated_until` не теряет долг при долгом отсутствии.
3. Правка серии: «только это», «это и будущие» (правило закрывается и создаётся новое), «вся серия»; выполненные вхождения не меняются.
4. Таймер хранит отрезки, а не тикает в фоне; перевод часов назад даёт вопрос пользователю.
5. Статистика привычек считается запросами; кэш — только если замеры покажут медленную работу.
6. Синхронизация календарей — каждые 15 минут и по команде; погода кэшируется на 30 минут.
