## 1. Итог

Компоненты, данные, взаимодействие, ошибки и проверки описаны в проектных документах. Это **материал для рассмотрения**, а не разрешение писать код. Прежде чем начинать Ф0, владелец обсуждает [план Ф0](P0_PLAN.ru.md) после утверждённых архитектуры, схемы, API и модулей; программирование начинается только после отдельного явного разрешения. Изменения после ADR-019–021 и новая редакция схемы должны учитываться при этом рассмотрении.

## 3. Как проверена сама структура

- **Покрытие требований.** Каждая обязательная функция из PRODUCT сопоставлена с таблицами схемы, командами API и модулем (§5). Непокрытых функций нет.
- **Схема.** Весь SQL из SCHEMA выполнен во временном кластере PostgreSQL 18: 63 инструкции, 45 таблиц, ошибок нет. Кластер удалён. Отдельно проверено, что база сама отклоняет нарушения правил продукта: задача без приоритета, срок без времени, второе вхождение разовой задачи, второй активный таймер той же привычки (активные таймеры разных привычек разрешены), блок с концом раньше начала, разрешение на удаление файлов, повтор одной отметки привычки. Все 13 случаев повели себя как задумано. Это проверяло прежнюю редакцию схемы из 45 таблиц. Новая редакция с таблицей отрезков (46 таблиц) пока не выполнялась; повторные проверки отложены владельцем до программирования.
- **Согласованность.** Имена команд в API совпадают с именами в схеме и модулях; ссылки между документами проверены; обе языковые версии сверены по структуре.
- **Чего эта проверка не доказывает:** что программа будет работать. Это покажут тесты по фазам и реальные проверки после программирования.

## 6. Предлагаемые технические правила на утверждение владельца

Небольшие структурные предложения из CP05–CP07 на рассмотрение владельца; этот отчёт не закрепляет их как окончательные:

1. Равенство в автоплане: при одинаковых сроке и приоритете раньше идёт задача, созданная раньше (порядок `uuidv7`). План детерминирован.
2. Вхождения повторяющихся задач создаются на 60 дней вперёд; курсор `generated_until` не теряет долг при долгом отсутствии.
3. Правка серии: «только это», «это и будущие» (правило закрывается и создаётся новое), «вся серия»; выполненные вхождения не меняются.
4. Таймер хранит отрезки, а не тикает в фоне; перевод часов назад даёт вопрос пользователю.
5. Статистика привычек считается запросами; кэш — только если замеры покажут медленную работу.
6. Синхронизация календарей — каждые 15 минут и по команде; погода кэшируется на 30 минут.

## 7. Перенесено на после программирования (условие владельца)

- Живые проверки: голосовой помощник, микрофон и ключевая фраза (`cache/feasibility/mic_wake_test.py`), отслеживание задач, напоминания, синхронизация.
- Проверки без кода, отложенные владельцем: прослушивание Vosk 0.9, память интерфейса Flutter.
- Приёмка на реальной машине с 8 ГиБ только с CPU — в фазе Ф7.

- Происхождение и лицензии выбранных голосов; условия Tavily и MET Norway (ADR-014).
- Сертификат подписи кода (ADR-015).
- Цена и выпуск лицензий остаются открытыми; запуск оплаты следует после программной реализации и ручных проверок (ADR-017).
- Направление Android (DD10) — после первого выпуска для Windows; контракт API уже рассчитан на второго клиента.
