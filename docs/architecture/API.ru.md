# Каталог API ядра, версия 1

[English version](API.md) · [Технические детали](TECHNICAL_DESIGN.ru.md) · [Схема базы](SCHEMA.ru.md) · [Модули](MODULES.ru.md) · [Фундамент CP01–CP02](FOUNDATION_DESIGN.ru.md)

Статус: предложение agent-02 (PLAN-024), 2026-11-04. На проверке у владельца. Полный перечень команд, запросов и событий между интерфейсом, голосовым помощником и ядром. Имена окончательные для v1, если владелец не попросит иное. Код не пишется до утверждения.

## 1. Соглашения

- Транспорт и защита — [технические детали](TECHNICAL_DESIGN.ru.md) §1 (ADR-015): `127.0.0.1`, токен запуска, проверка `Host` и `Origin`.
- Команда: `POST /v1/commands/<Имя>`. Запрос на чтение: `POST /v1/queries/<Имя>` (тело JSON; запросы ничего не меняют и не вызывают модель). События: WebSocket `/v1/events`.
- Конверт команды (CP01 §2.3): `protocol_version`, `request_id`, `action_id` (стабилен при повторе), `origin` (`ui`, `voice`, `assistant`, `proactive`, `sync`), `expected_revisions`, `reference` (мгновение и зона для толкования «завтра»), `payload`, `approval_id`.
- Результат команды — одно из состояний: `AppliedLocal`, `QueuedExternal`, `NeedsClarification`, `NeedsConfirmation`, `NeedsInput`, `Conflict`, `Denied`, `Unavailable`, `Failed`. Вместе с ним — `action_id`, новые ревизии и при необходимости модель чтения.
- `NeedsConfirmation` возвращает `approval_id` и точное содержимое для показа. Подтверждение — команда `Approve` с этим `approval_id`; изменение любого существенного поля требует нового подтверждения.
- Подтверждение по умолчанию требуется для изменений задач от ассистента; отменяется отзываемыми разрешениями (`capability_grant`). Значок 🔒 ниже — подтверждение **всегда**, разрешение его не отменяет.
- Голос: колонка «Ассистент» отмечает команды, доступные модели как инструменты (§14). Остальные выполняются только из интерфейса.

## 14. Инструменты ассистента

Модель получает не HTTP-API, а реестр типизированных инструментов. Каждый инструмент — обёртка над одной командой или запросом из таблиц выше с `origin = assistant` и урезанной схемой полей (только то, что можно сказать голосом). Правила:

1. Модель предлагает вызов; ядро проверяет схему, цель, разрешения и подтверждения, как для интерфейса. Ответ модели не является полномочием.
2. Неоднозначная цель («перенеси встречу», а встреч две) — всегда `NeedsClarification`, даже при разрешениях.
3. Факты в ответе (время, количество, успех) берутся из результата команды, а не из текста модели.
4. Данные из почты, поиска и файлов передаются модели как недоверенный текст и не могут вызывать инструменты сами по себе.
5. Для экономии контекста в профиле 8 ГБ модель получает инструменты группами по намерению (задачи, привычки, календарь, сведения, устройство), а не все сразу.

## 15. События

Все события — подсказка перечитать данные: `{"type", "revision", "resources"}`; пропуск ревизии означает полный снимок (CP01 §2.4).

| Тип | Когда |
| --- | --- |
| `changed` | зафиксирована любая команда; `resources` — затронутые типы и идентификаторы |
| `audio_state` | смена состояния звука (для круга ассистента и кнопки микрофона) |
| `transcript` | промежуточный и итоговый текст распознавания текущей реплики |
| `assistant_text` | текст ответа по предложениям, синхронно с синтезом |
| `notification` | сработало напоминание, появилось подтверждение, пришла сводка |
| `approval_requested` | ассистент ждёт подтверждения |
| `resource_progress` | прогресс загрузки моделей |
| `entitlement` | изменился доступ (истёк, импортирована лицензия) |
| `maintenance` | бэкап, миграция или восстановление: запись временно недоступна |
| `shutdown` | ядро завершается |

## 16. Коды ошибок

Закрытый перечень `error.code` (текст для пользователя — на языке интерфейса): `validation_failed`, `missing_field`, `not_found`, `revision_conflict`, `action_reused`, `stale_plan`, `ambiguous_target`, `confirmation_required`, `permission_denied`, `access_expired`, `clock_rollback`, `resource_unavailable`, `memory_insufficient`, `network_unavailable`, `provider_error`, `provider_reauth`, `maintenance`, `db_unavailable`, `unsupported_protocol`, `internal`.
